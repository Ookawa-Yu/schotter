Why Are We Still Learning Programming?

In 2026, artificial intelligence can already generate working code from a sentence written in natural language, and this ability continues to improve rapidly. For designers and artists, learning programming may therefore seem increasingly unnecessary. If a machine can write the code for us, why should we spend time learning to do it ourselves? I believe that we are not learning programming to compete with AI over who can produce code faster. We are learning it to understand computation as a creative medium and to express our ideas through that medium with greater precision and control.

In The Art of Code, Dylan Beattie demonstrates that programming is much more than a technical method for solving practical problems. Conway’s Game of Life produces complex and unpredictable patterns from only a few simple rules. The Mandelbrot set transforms a mathematical relationship into a visual structure of almost infinite complexity. Esoteric programming languages such as Piet, Chef and Rockstar make programs resemble abstract paintings, recipes and rock lyrics. These examples show that code does not always need to remain invisible behind an artwork. Its rules, structure and process of execution can become meaningful parts of the work itself. In this sense, programming can be an expressive medium, just like painting, music or photography.

AI can generate code, but it does not automatically understand what a creator truly wants to express. For example, the request “create a generative poster that feels unsettling” communicates a general mood, but it does not explain how the visual elements should change, how much randomness the system should contain, or what relationships should exist between its colours, shapes and movements. Turning a vague feeling into a meaningful system still requires the creator to make specific decisions. Learning programming trains us to translate an intention into rules, conditions and relationships. It prevents an idea from remaining only a sentence given to a machine.

Understanding code can also change what we are capable of imagining. Painters learn how pigments mix and behave, while photographers learn how light, lenses and exposure shape an image. In the same way, digital creators benefit from understanding loops, randomness, data and algorithms. Technology is never completely neutral because every tool makes certain actions easy, others difficult, and some possibilities almost invisible. A creator who does not understand code may be limited to the options provided by an AI system or existing software. A creator who understands the medium can question those options, modify their boundaries and pursue results that the tool’s designers did not anticipate.

Even if AI writes most code in the future, people will still need to evaluate what it produces. A program that runs successfully is not necessarily well designed. It may contain hidden errors, behave unpredictably in unusual situations, or technically function without expressing the creator’s intention. If we cannot understand the material being used, we become dependent on the machine’s own explanation of whether its work is correct. Programming knowledge allows creators to examine the system, recognise its limitations and take responsibility for the final result. The human role may move away from manually producing every line of code, but direction, interpretation and criticism will remain important.

Learning programming, therefore, does not require us to reject the convenience of AI. Instead, we should allow AI to handle repetitive and time-consuming work while protecting our own ideas, judgement and creativity. AI can help us produce a work more efficiently, but it should not decide what the work is worth expressing. Human imagination should control the direction of the system: we should define the questions, design the rules and choose which possibilities deserve to be developed. The machine can then help us expand and realise those possibilities.

We are here because programming is more than the manual production of instructions. As Beattie demonstrates, code can become image, music, language, performance and play. AI may increasingly write those instructions for us, but this makes an understanding of the medium more important rather than less. Without that understanding, artists can request outputs but cannot fully examine or reshape the systems producing them. The most important question in the future may not be who can write the most code. It may be who can use code and AI while remaining in control of their imagination—and turn an original idea into something that did not exist before.
